# plazir18 Agent TUI Expansion Plan

**Goal**: Evolve the Ratatui surface of plazir18 into the best *open, minimal* coding-agent TUI — a breed of [OpenCode](https://opencode.ai) UX + [codex-titanium](https://github.com/VeigaPunk/codex-titanium) philosophy — while preserving the existing excellent zero-CPU tmux multi-panel wall.

## Vision

- **Minimal clutter** like OpenCode: primary conversation view, thin status, slash commands, almost no chrome.
- **Dual mode**:
  - `plazir18` / `--wall` (or existing egui + `--tui` wall): keep the 18-panel tmux monitor (event-driven, vt100 live tails).
  - `plazir18 agent` or `--agent` (new default for TUI path): full agent loop.
- **Titanium DNA**: unrestricted defaults optional (`approval_policy = never`, `sandbox_mode = danger-full-access`), Godspeed base directive, multi-agent readiness, DS4CC marketplace awareness later.
- **OpenCode DNA**: `/connect`, `/models`, `/init`, multi-session, `@file`, inline tools, plan/build modes, shareable sessions later.

## Must-have Auth & Routing

| Provider | Auth style | Notes |
|----------|------------|-------|
| **ChatGPT / Codex** | Official OAuth PKCE (client `app_EMoamEEZ73f0CkXaXp7hrann`, auth.openai.com) | Same as Codex CLI / OpenCode openai plugin. Token refresh. Account ID from JWT. |
| **Grok / xAI SuperGrok** | Browser PKCE or device-code to accounts.x.ai / auth.x.ai | Subscription counts against SuperGrok/X; no separate API key required. |
| **OpenCode Zen** | API key after login at opencode.ai/auth (or console) | Bearer to `https://opencode.ai/zen/v1/*` (responses / messages / chat/completions). Curated models. |
| **Local** | OpenAI-compatible base URL + optional key | Auto-detect Ollama (`11434`), vLLM, llama.cpp, etc. Preferred when available. |

Model router: config-driven (TOML or env), local-first, explicit fallback order. Simple reqwest + serde OpenAI-compatible client first.

## Agent Workflows (OpenCode parity, minimal)

- Multi-session (list / switch / new).
- Modes: at least *build* (full tools) and *plan* (read-only / propose).
- Tools: shell, read/write/edit file, list dir (permissions gated by config; Titanium unrestricted available).
- Slash commands: `/connect`, `/models`, `/init`, `/session`, `/help`, `/clear`.
- `@path` fuzzy file reference into context.
- Project context: `AGENTS.md` or equivalent generated by `/init`.
- Inline tool result rendering in the conversation stream.
- Status bar: model · mode · tokens · session.

Later: multi-agent spawn (leverage existing xbrd / godspeed patterns and tmux isolation), marketplace plugins, share links.

## Architecture (Rust-only, Ratatui)

```
src/
  auth/
    mod.rs          # ProviderAuth trait, store (~/.local/share/plazir18/auth.json)
    chatgpt.rs      # OpenAI OAuth PKCE
    grok.rs         # xAI OAuth / device
    zen.rs          # API key + validation
    local.rs        # discovery + health
  provider/
    mod.rs          # ModelRouter, OpenAI-compatible client
  agent/
    mod.rs          # session, messages, tool dispatch
    tools.rs
  tui/
    wall.rs         # existing dashboard (moved)
    agent.rs        # new minimal chat TUI
  ...existing modules...
```

Immediate-mode Ratatui, simple state machine, crossterm. No heavy retained frameworks. Keep binary lean; feature flags if needed (`wall`, `agent`).

## Non-goals (for v0 agent)

- Full MCP server hosting.
- Heavy retained UI or web frontend.
- Replacing the egui wall (keep both).
- Perfect upstream OpenCode feature parity day one.

## Success criteria

- `plazir18 agent` feels as uncluttered as OpenCode.
- One command to connect Grok or ChatGPT subscription *or* Zen *or* local model.
- Real agent workflows (edit files, run commands) with transparent permissions.
- Existing `--tui` / wall remains excellent and zero-CPU when idle.
- Pure Rust, MIT, ready for DS4CC / xbgst ecosystem.

Godspeed.
